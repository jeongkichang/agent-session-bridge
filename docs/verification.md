# 검증 기록

## 2026-09-13 — 0.2.0

- Node 24.19.0, pnpm 10.4.1. 실행 중인 업무 브로커를 유지하고 별도 임시 디렉터리·SQLite·가짜 Claude 실행기로 검증했다.
- 수정한 결함 5건: 교체된 옛 발신자의 신규 전송 허용, lease 만료와 heartbeat/재등록 순서의 불일치, JSON 이스케이프로 정상 32 KiB 본문이 거절되는 문제, Claude 전달 인자의 `--` 뒤에 추가 설정이 붙는 문제, 시그널 종료를 성공으로 보고하는 문제.
- 자동 테스트 17건 통과, 타입 검사 통과. 기존 동일 ID 재시도·권한·중복 브로커 시작 검증을 포함한다. 새 테스트는 위 결함 경계와 본문을 포함하지 않는 peer별 요청 현황·오류 복구 안내·버전 표시를 확인한다.
- 실제 stdio MCP 접속기를 유지한 채 격리 브로커를 중지/재기동해 약 10초 내 heartbeat 복구, 완료 답변 보존, 전달 중 요청의 불확실 상태 보존, 새 요청/답변 왕복을 확인했다. 이전 요청의 Channel 알림은 재전송되지 않았다.
- 자동 MCP 호스트·가짜 Claude 검증이며 새 버전의 실제 Claude 모델 호출 또는 업무 피어 재연결 완료를 뜻하지 않는다. 설치 후 업무 세션의 버전·왕복 검증은 별도 단계다.
- 답변의 자동 Channel 통지와 idle Codex 자동 깨움, 재시작한 MCP의 이전 peer 소유권 승계는 추가하지 않았다. 답 대기 보고 전에 원래 요청을 조회해야 하며, 오래된 요청은 소유자 CLI로 확인한다.

## 2026-09-12

- Node 26.5.0, Claude Code 2.1.269, Codex CLI 0.153.4.
- 자동 테스트 11개 통과: SQLite 상태·멱등성·peer lease·재시작, HTTP 인증/Origin/Host/크기 제한, 실제 stdio MCP 양방향 교환, 다중 프로세스 시작 경합. 독립 코드 검토에서 발견한 동시 시작, 만료된 peer의 이름 재사용, CLI 재전송의 원래 수신자 유지 문제를 보완하고 재검토를 통과했다.
- 22:33 KST: 별도 Claude 시험 세션에 서로 다른 nonce 2개를 **Channels 알림으로** 전달했다. Codex MCP 접속기의 `send_message`로 접수하고 `wait_reply`로 실제 Claude 모델의 `reply` 호출 결과를 읽었다. 두 원래 요청 ID와 nonce가 모두 정확히 일치했다.
- 시험 세션에는 프로젝트 파일·DB·브라우저 도구를 주지 않았다. 기존 업무 세션에는 메시지를 보내지 않았다.
- 22:44 KST: 같은 Claude 시험 대화를 종료한 뒤 `--resume`으로 다시 열었다. 기존 대화의 지시를 유지한 상태에서 새 nonce 2개를 채널로 보내 두 요청 모두 정확한 답장을 받았다. 실제 모델 왕복은 총 4건이며 재개 후에는 새 peer UUID로 연결했다.
- 알림을 사용자 입력으로 위장하거나 직접 답변을 DB에 쓰지 않았다. SDK만으로 시험한 경로와 실제 모델 호출을 구분했다.
- 현재 Codex 데스크탑은 외부 App Server 제어 소켓이 노출되지 않아 idle 자동 깨움은 미구현이다. 현재 제공하는 수신 경로는 MCP 조회·대기다.

실제 채널 시험에서 초기 화면에 잠깐 `no MCP server configured with that name` 안내가 남았지만, peer 등록과 실제 채널 수신·회신은 성공했다. 초기 화면 문구만으로 성공 여부를 판정하지 않고 끝까지 왕복 결과를 확인했다.

개인 시험의 원문·세션 ID·인증 정보는 이 저장소에 포함하지 않는다. Channels의 조직 정책·개발 채널 확인과 기존 권한을 그대로 적용한다.
